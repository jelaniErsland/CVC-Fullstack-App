## Result

Mobile Month retains the seven-column date grid but replaces unreadable event fragments with category dots, a busy-day count and a clearly selected date. The agenda directly beneath the grid lists every item on that date with its actual time, headcount or staffing count, meal contact or permitted assignment roster, and exact inspector selection. A control before the grid scrolls and moves keyboard focus to the agenda. At 390px the first agenda card enters the initial viewport. At 320px the grid can extend beyond it, so the same prominent jump offers direct access without forcing tiny targets into date cells. The agenda header has a labeled **Open Day** action and retains **Day details** separately.

Authenticated and bearer Quick View show the selected day's Breakfast and Lunch headcounts before the Month grid, without opening an inspector. **Not recorded**, **0**, a positive count, and **Not scheduled** remain distinct. The existing single meal-contact text and time appear only from the authorized meal projection; meal entries do not acquire volunteer rosters or staffing fractions. Ordinary food-service shifts still use normal assignment presentation. Selecting another mobile date updates the summary and route. All Quick View views remain read-only, and bearer Quick View never gains volunteer identities.

Visible assignment rosters keep the first three names and the accessible `+N more` disclosure. A green check-circle means Confirmed, an amber clock means Awaiting reply, and a red X-circle means Can't make it. A visible legend explains the icons on mobile without hover; each roster icon also has an accessible name and tooltip. The existing active-staffing fraction is unchanged, so a declined response is not counted as active.

The direct-navigation addendum is included. Desktop Month day numbers and desktop Week day headings open Day view for their exact date. Empty Month cell space still opens the authorized creation workflow, while event chips still open the exact item inspector. On mobile a date selects the agenda, then **Open Day** opens the full Day view. Calendar, authenticated Quick View and bearer Quick View retain their own route context. Keyboard focus, Back navigation and project-scoped Quick View links were exercised.

The desktop empty-area follow-up adds double-click Day navigation to Month cells and both Week context and timed areas. A single click still opens the existing planner; the first click waits 300ms so a double-click can cancel it. Keyboard Enter opens the planner immediately. Selecting an event or a day heading cancels any pending empty-area click. Day's own empty slots and mobile date selection are unchanged. Quick View leaves empty areas inert because it is read-only; its labeled day-number and Week-heading routes remain available. The 300ms pointer delay is the only interaction tradeoff, and the focused browser regression checks the complete single/double-click outcome.

The established desktop Day, Week, Month and List layouts, task colors, filters, stable navigation group, List time column, project-day access, schedule links and inspector/editing boundaries remain in place. No server action, schema, RLS, notification, backup or deployment code changed.

## Visual comparison and responsive findings

The final 1440px views remain recognizably the approved Calendar. The Month grid retains its desktop event density; day-number hover and focus now indicate the direct Day route. The 390px Month view brings the selected-day heading and first schedule row into the first viewport. Quick View replaces the proposal's illustrative meal blocks with the existing application card style and keeps the daily label directly above them. The roster icons use the approved restrained colors and a compact legend. At 320px, normal and enlarged text, the agenda is scroll reachable and its jump action remains above the grid. No document-level horizontal overflow was observed at 320, 390, 768, 1024 or 1440px in the focused browser checks. The 320px initial viewport cannot show both a full month grid and the agenda; the jump is the intentional small-phone access path.
