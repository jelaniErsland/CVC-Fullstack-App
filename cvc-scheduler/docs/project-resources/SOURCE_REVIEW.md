# Implemented baseline and evidence
Source inspected at `e2eeed8`; source contracts outrank historical planning prose. This is repository inspection, not a new production audit.

| Area | Current implementation and design consequence |
| --- | --- |
| Planning baseline | [Product requirements](../PROJECT_LOCAL_PRODUCT_REQUIREMENTS.md) explicitly describes future behavior. Its template Follow-up Contact defaults, automatic reminders and one-click confirmations cannot be assumed operational from that document. |
| Current release | [CURRENT_STATE](../CURRENT_STATE.md), [Batch 2 release](../12_48_BATCH_2_RELEASE.md) and Git history identify `ca54020` as deployed, followed by documentation and harness-only commits. |
| Admin identity | [verified-admin-context](../../lib/auth/verified-admin-context.server.ts) calls verified Auth user, derives contact/grants/workspaces server-side. [Grant model](../../lib/auth/grant.ts) includes capabilities, status, validity and revocation. Roles are descriptive, not sufficient authority. [Granted workspaces](../../lib/workspaces/granted.ts) is RLS-bound. New resource permissions must follow this model. |
| Volunteer identity | The [current lookup replacement](../../supabase/migrations/20260908130000_volunteer_lookup_last_name_and_attention_seen.sql) matches normalized last name plus exact email/normalized phone against active/ready profiles and active workspaces. It supersedes the older full-name comparison; the RPC argument retains the legacy name p_full_name. Duplicate matches inside a workspace fail closed; multiple workspaces produce opaque HMAC project choices. Shared household matches are not a basis for unioning identities. |
| Volunteer sessions | [Lookup route](../../app/v/lookup/route.ts) enforces bounded same-origin JSON POST, issues an HttpOnly browser-session cookie under /v, and does not expose the credential in JSON. Lookup token DB lifetime is 24 hours. [Personalized access exchange](../../app/v/access/[token]/route.ts) validates a schedule credential, installs the same cookie and redirects to a clean schedule URL. Issued email links can have a different DB expiry (current schedule dispatch requests 720 hours). No separate persistent remembered-device registry was found; browser-session continuity is not a proven secure-device feature. |
| Volunteer home | [Home server](../../lib/volunteerScheduleAccess/home.server.ts), [home component](../../components/VolunteerHomeDashboard.tsx) and [12.47 migration](../../supabase/migrations/20260922150000_project_hero_volunteer_home.sql) provide schedule, meal menu, away periods and photo reference. They do not implement project information/documents. |
| Response routes | [respond route](../../app/respond/[token]/page.tsx) and [response token model](../../lib/responseTokens/token.ts) represent one assignment. Schedule access is a different credential family. Do not turn a one-assignment response token into a workspace resource pass. |
| Presets | [preset.ts](../../lib/tasks/preset.ts): name, description, type, default needed count, volunteerVisible, system flags, color, custom-field definitions and lifecycle. Structured instructions, document references and revision history are absent. The older [read contract](../../lib/tasks/readModelContract.server.ts) is useful but includes historical availability flags; check live route and migrations before relying on them. |
| Scheduled work | [item.ts](../../lib/calendar/item.ts): workspace/item IDs, optional preset ID, schedule/date/time/timezone, notes, custom values, needed count, lifecycle, publication and optimistic version. Repeated creation makes independent saved occurrences; there is no new series to invent. Exact item and assignment IDs remain authoritative. |
| Calendar/Quick View | [route read](../../lib/calendar/routeRead.server.ts), [Quick View adapter](../../lib/calendar/quickView.server.ts), [shared-link server](../../lib/projectQuickViewAccess/server.ts) preserve route and publication context. Current bearer contract already includes a bounded published-work/assigned-name projection from earlier releases; no additional resource or identity fields may be added. Project-day summaries are not instruction ownership records. Meals have nullable headcounts and their own free-text contact fields. |
| Contact semantics | Existing assignment notification projections carry an assignment Follow-up Contact. A preset's proposed reporting contact must not silently replace that response/help contact. Meal contact is neither of these. |
| Project photo | [files adapter](../../lib/projectPhoto/files.server.ts) is explicitly loopback-only, rejects Vercel, accepts bounded still images and re-encodes variants without EXIF. [server](../../lib/projectPhoto/server.ts) requires the existing photo RPC and calendar.edit. Production uploads remain disabled; no document-capable production object store is established. |
| Notifications | [initial email](../../lib/notifications/initialAssignmentEmail.server.ts), [Calendar dispatch](../../lib/calendar/assignmentNotifications.server.ts), [Communications model](../../lib/notifications/communications.ts) and [dispatch](../../lib/notifications/communicationDispatch.server.ts) use existing preview/claim/finalize ledgers and recording/Resend transports. Welcome currently points to project-independent lookup; schedule messages issue personalized schedule links. Preview fingerprints, live claim rechecks and unknown-provider outcomes must survive. |
| Backup/recovery | [native backup](../../scripts/production-backup/Invoke-ProjectLocalProductionBackup.ps1), [setup](../INDEPENDENT_PRODUCTION_BACKUP_SETUP.md), [runbook](../PRODUCTION_BACKUP_RECOVERY_RUNBOOK.md), [12.47 restore proof](../12_47_AUTH_STORAGE_RECOVERY.md). Current code uses native PostgreSQL tools; older prose still mentions CLI/Docker dumps. Six-member age-encrypted DB package, daily 03:15 task, 14 daily/8 weekly retention, DPAPI connection secret and safe failure notification. Empty Storage metadata recovery was proven; actual object BLOB recovery was not. |
| Shared UI | [DisclosureSection](../../components/DisclosureSection.tsx) already has one rotating chevron. Reuse it, ActionMenu, IconButton, existing drawer/sheet behavior and [ldcProjectName](../../lib/projectIdentity.ts); do not add a second disclosure indicator or hard-code a project. |
