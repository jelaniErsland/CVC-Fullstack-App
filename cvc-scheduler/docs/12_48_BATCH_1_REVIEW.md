## Final assignment-visibility addition

Admin Calendar Day and List show up to three assigned volunteer names directly below task title/time, with explicit Confirmed, Awaiting reply or Declined wording. A shared native disclosure reveals every remaining name without opening the inspector. Empty assignments say “No volunteers assigned”; unavailable assignment data is identified separately. Fractions still come from the existing coverage model, where declined responses do not count toward staffed positions and pending responses are not described as confirmed.

Names are selected from the existing authorized projection for the exact scheduled item ID. Independent repeated occurrences retain their own names/responses; no title-based matching or new query was added. Authenticated read-only Quick View receives this UI only with the existing volunteer-view permission. Bearer Quick View gains no new roster UI or data access. Meals show headcount and one contact without any roster; ordinary food-service shifts use the task roster.

The final visual comparison checked desktop/mobile Day and List captures, including expanded lists. The first pass left a redundant task-category line between timing and names; it was removed where a roster is shown. Names wrap within cards, status words remain readable without color, and the final expanded name was scrolled above fixed mobile navigation. ## Final behavior

The existing 12.47 photo flow remains: project-scoped read, upload or replacement, independent desktop/mobile crop coordinates, version-checked save, removal, and scoped protected image delivery. The mutation route, storage adapter, RPC, and permission checks were not edited. `readAdminProjectPhoto` still requires the single authorized workspace and only enables editing when local photo storage, `uploads_enabled`, and `calendar.edit` all permit it. The editor still uses the existing 6 MB validated image path and CAS version; uncertain saves do not delete a possibly published asset. The no-photo Overview now has a compact text identity with Add project photo beside it. A configured photo appears as a 150px desktop / 110px mobile panoramic banner with its existing focal crop and a nearby ellipsis menu for Change project photo. A [read-only capability fixture](../../previews/12.48-batch-1/after/overview-photo-readonly-390.png) shows the photo while withholding that edit control. Identity text remains readable without the image. The fixture captures establish rendering and crop behavior, not behavior against a real project's photograph or session.

Overview retains To review and Next up. At mobile widths it shows the first two review groups and an explicit View all follow-ups link; the full list remains on wider layouts. Matching records with the same displayed context and same operational summary are grouped with an item count, so identical rows do not masquerade as different work. Full times and meal-specific menu/provider summaries remain. The old bottom Quick actions repeated persistent navigation and were removed. A direct **New task** action appears only with `tasks.edit`; `/admin/tasks?create=1` opens the existing task form, with the task route independently enforcing edit permission. Calendar and volunteer shortcuts were not relabeled as creation flows.

Grouped Overview schedule and review links now open the existing authorized Calendar day without selecting a constituent item; both records remain available there. A one-record row retains an `item` inspector deep link. A regression uses two distinct records with the same visible title, date, time and operational state and checks both group destinations, plus the single-item URL. The browser fixture follows both grouped links and finds both records on the destination day.

Overview columns now size from available content width. At 1440px with 200% text they stack instead of squeezing two panels. The desktop project-context card expands to contain its name and the sidebar scrolls. Normal mobile navigation keeps Overview, Calendar, Volunteers, Attention and More with labels. When available width measured in root text units is too small, it becomes a single row of Overview, Calendar and More; Volunteers and Attention move into More. The More list scrolls independently above the measured bottom bar and safe area. The last link, close control, keyboard focus and final page action were checked for actual reachability.

The shared `ActionMenu`, `DisclosureSection` and `IconButton` patterns are documented and demonstrated in the isolated foundation fixture. ActionMenu supports an ellipsis trigger, labeled items, keyboard movement/Escape/focus restoration, outside dismissal, and an optional in-menu confirmation. DisclosureSection uses native details/summary with a descriptive collapsed label. The previous closed capture had no visible disclosure marker. It now has one subtle chevron, with the native marker suppressed to avoid a duplicate; the chevron rotates on expansion. IconButton has a required accessible name and 44px target. Primary or consequential actions retain visible wording. Fixture routes and mocked actions exist only in `%TEMP%/project-local-12-48-fixture`; they are absent from product navigation and the production build.

Quick View retains the Batch 1 route-context repair. The two empty circles beside non-meal staffing in the earlier fixture were category and status pills whose synthetic values did not map to labels. Read-only Quick View now suppresses those secondary pills; the meaningful count and publication state remain. Breakfast and Lunch instead show a daily headcount directly on read-only entries (including the narrow month abbreviation), with contact text visible in list view. Their read-only inspector contains only the scheduled day/time, prominent headcount and one meal contact. Missing is **Not recorded**, while saved zero is **0**. Missing contact is **Not assigned**. Meal entries do not show helper counts, staffing fractions or vacancies; ordinary food-service volunteer assignments remain separate in the underlying Calendar model. The existing `meal_contact` is one nullable free-text field and is included in the bearer read RPC. It supports one displayed contact label, but it is not an identity-linked, validated designated-contact relationship; that requirement needs a later data-contract decision if stronger semantics are intended. No schema or projection was changed in Batch 1.

The `/admin/quick-view` and `/qv` component routes were opened with a date but **without a `view` parameter**. Both defaulted to Month and exposed Breakfast/Lunch headcounts before any inspector opened. This was also checked on the actual authenticated local Quick View route using real Auth/RLS. Desktop chips lead with “Breakfast · —” / “Lunch · 0”; at 390px the month uses B/L plus number or dash. A visible legend explains both forms. Mobile month cells remain dense and small, and retain the existing three-item limit (six on desktop), with overflow opening Day view. Busy-day meal discovery, larger text and food-contact comprehension remain Batch 2 review points. The default opens the current month; meals on another date require normal Calendar navigation. Production-role smoke remains pending a usable project session.

Visible project names use `LDC` exactly once through a reusable formatter. The formatter uses the supplied name; there is no hard-coded city. The initial volunteer sign-in and authentication flow were untouched.
